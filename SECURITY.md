# Security and disclosure

Never put credentials, service-account files, customer exports, private packages or authentication cookies in issues or pull requests. Report security issues privately through the repository owner's GitHub contact route. Public issues are for non-sensitive defects; no dedicated vulnerability email is advertised here.

A theme is presentation, not an authorization boundary. Review CSS and future plugin code before deployment. Keep credentials in server secret management, pin reviewed theme commits, enforce scope at the provider, and separate validation from production. Starter integrations are read-only; authenticated writes need a separately reviewed product provider.
